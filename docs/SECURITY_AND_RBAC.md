## 1. Cryptography & Password Hashing

The platform enforces modern, zero-deprecation cryptography:

1. **Argon2id Key Derivation:**
   - Password hashing is implemented strictly with `pwdlib[argon2]>=0.2.0`.
   - Legacy libraries (`passlib`, unmaintained raw `bcrypt`) are completely excluded.
   - **Non-Blocking Execution:** To prevent CPU-intensive Argon2 key derivation functions from blocking the Python AsyncIO event loop, verification runs inside an asynchronous thread executor via `verify_password_async()`.

```python
# backend/src/app/core/security.py
async def verify_password_async(plain_password: str, hashed_password: str) -> bool:
    loop = asyncio.get_running_loop()
    return await loop.run_in_executor(
        None,
        verify_password,
        plain_password,
        hashed_password,
    )
```

## 2. JWT Token Lifecycle & Valkey Revocation

Authentication is stateless via JSON Web Tokens (JWT) using `HS256` signed by `SECRET_KEY` (minimum 32-byte high-entropy string).

### 2.1 Token Payload Claims

```json
{
  "sub": "55c22f9e-782e-4192-a097-6a44c4e703c5",
  "is_superuser": true,
  "exp": 1787233750,
  "iat": 1787230150,
  "jti": "fbdc092a-41c6-4d79-824f-bc31c0480b2d"
}
```

- `sub`: Canonical UUID string of the authenticated user.
- `is_superuser`: Embedded boolean claim for rapid, zero-query RBAC gating.
- `jti`: Unique UUID4 token identifier for instant revocation.

### 2.2 Instant Session Revocation (Logout)
When a client invokes `POST /api/v1/auth/logout`:
1. The token's `jti` is stored in **Valkey** with a key `revoked_token:<jti>`.
2. The Valkey TTL is calculated dynamically based on the remaining lifetime (`exp - now`), ensuring blacklisted entries auto-expire when the token naturally expires.
3. Subsequent requests using the revoked token are immediately rejected with `401 Unauthorized`.

## 3. Interactive Swagger UI & Scalar Authorization

The OpenAPI 3.1 specification configured in [`openapi.py`](file:///home/pat/Business/LiteStar/backend/src/app/core/openapi.py) declares two native security schemes:

```python
components=Components(
    security_schemes={
        "BearerAuth": SecurityScheme(
            type="http",
            scheme="bearer",
            bearer_format="JWT",
            description="Enter JWT Bearer token directly: Bearer <token>",
        ),
        "OAuth2Password": SecurityScheme(
            type="oauth2",
            flows=OAuthFlows(
                password=OAuthFlow(
                    token_url="/api/v1/auth/login",
                    scopes={},
                )
            ),
            description="Standard Swagger / Scalar OAuth2 username & password login",
        ),
    }
)
```

### Dual Ingestion Login (`POST /api/v1/auth/login`)
The `/login` route dynamically handles:
1. **JSON Payloads:** `{"email": "...", "password": "..."}` or `{"username": "...", "password": "..."}`
2. **OAuth2 Form-Data:** `application/x-www-form-urlencoded` fields (`username` and `password`) generated by the native Swagger "Authorize" padlock modal.

Both flows return the RFC 6749 standard token response:
```json
{
  "access_token": "eyJhbGciOiJIUzI1Ni...",
  "token_type": "bearer",
  "expires_in": 3600
}
```

| `/api/v1/auth/login` | POST | None | Public | 401 on bad credentials |

## 5. Security Guard Implementation

The [`SuperuserGuard`](file:///home/pat/Business/LiteStar/backend/src/app/presentation/guards/auth_guard.py) enforces a two-phase check:

```python
class SuperuserGuard:
    def __init__(self) -> None:
        self._auth = JWTAuthGuard()

    async def __call__(self, connection: ASGIConnection, handler: RouteHandlerType) -> None:
        # Phase 1: Validate JWT signature, expiry, and Valkey blacklist
        await self._auth(connection, handler)

        # Phase 2: Enforce superadmin claim
        if not connection.scope.get("is_superuser"):
            raise PermissionDeniedException("This endpoint requires superuser privileges.")
```
